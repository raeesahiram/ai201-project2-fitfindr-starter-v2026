# Local latency, cache improvement, and load check

Generated by `tests/measure_operations.py`. Model-dependent helpers return deterministic test strings so this measures local control-flow and MCP overhead without a live Gemini key. The search-listings MCP server and HTTP route are real. Cache data are reset before each comparison block.

## Baseline and after improvement

The baseline bypasses the new result cache and performs an MCP subprocess call on each trial. The after block uses the bounded process-local cache: its first identical request is a miss; the next two are hits. Times are end-to-end `run_agent` durations; the stage columns come from the JSONL records.

| Trial | Baseline total ms | Baseline MCP ms | After total ms | After MCP ms | After cache behavior |
|---:|---:|---:|---:|---:|---|
| 1 | 901.34 | 899.897 | 445.71 | 445.240 | miss |
| 2 | 454.12 | 453.588 | 0.25 | 0.077 | hit |
| 3 | 451.46 | 450.891 | 0.18 | 0.069 | hit |

Median total: 454.12 ms before and 0.25 ms after; repeated-query speedup 1816.5× in this run.

## Local HTTP load observation

The `serve.py` Flask app ran on an ephemeral `127.0.0.1` port. A normal-rate observation is one request with an empty search cache. The 10× burst is ten simultaneous identical requests; `serve.py` serializes agent runs, and the first search warms the local cache for the next nine. Deterministic outfit/fit-card helpers avoid live provider calls. Client and Flask request durations include time waiting for the serial request lock.

- Normal single request: **479.60 ms**, HTTP 200, success.
- Ten-request burst duration: **473.07 ms** (21.14 requests/second at the batch level).
- Burst request latency: min **463.87 ms**, median **467.31 ms**, p90 **469.16 ms**, max **470.36 ms**.
- Outcomes: 10/10 successful HTTP 200 responses. Flask process metrics: 11 requests, 0 failures, 459.76 ms average server duration.

The first MCP search took 460.364 ms; the remaining nine took 0.079 ms median from the warm cache. Similar client response times do not mean the cache missed: they include serial queue waiting before each fast agent run.

This is a local synthetic burst against one process, not a hosted deployment or a test of concurrent live Gemini quota behavior. The CLI command is `python app.py ask 'vintage graphic tee under $30'`; start the HTTP app locally with `python serve.py`. `gunicorn serve:app` is the documented host-compatible command, but was not run as a separate server or deployed here.
